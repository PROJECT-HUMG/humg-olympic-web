## Config

| File | Purpose |
|---|---|
| `src/i18n/index.ts` | i18next init — imports all JSON, registers namespaces, reads `app_language` from localStorage |

- **Library**: `i18next` + `react-i18next`
- **Default language**: `vi` (fallback: `vi`)
- **Default namespace**: `common`
- **Interpolation**: `escapeValue: false` (React handles XSS)

## Usage Patterns

### Basic
```typescript
import i18n from '@/i18n';

// Simple key
i18n.t('forum:page.title')

// With interpolation
i18n.t('roadmap:timeline.chapter', { num: 3 })
// → "Chương 3" (vi) / "Chapter 3" (en)

// With count
i18n.t('roadmap:chapterDetail.itemCount', { count: 5 })
```

### JSON key structure
```json
{
    "section": {
        "key": "Value",
        "keyWithParam": "Hello {{name}}"
    }
}
```
Access: `i18n.t('namespace:section.key')`

### HTML in translations
When a translation contains HTML (e.g. `<strong>`), use `dangerouslySetInnerHTML`:
```tsx
<p dangerouslySetInnerHTML={{ __html: i18n.t('roadmap:delete.confirmMessage', { name }) }} />
```

### Language switching
```typescript
import i18n from '@/i18n';
i18n.changeLanguage('en'); // or 'vi'
// Persisted to localStorage key: 'app_language'
```

## Adding a New Namespace

1. Create `src/i18n/vi/<name>.json` and `src/i18n/en/<name>.json`
2. Import both in `src/i18n/index.ts`
3. Add to `resources.vi` / `resources.en` objects
4. Add namespace string to `ns` array

## Rules

1. **No hardcoded Vietnamese/English** in `.tsx` / `.ts` files — always use `i18n.t()`
2. **Comments are OK** in Vietnamese — only user-facing strings need migration
3. **aria-labels count** — they are user-facing (screen readers), must use `i18n.t()`
4. **Both vi + en** — always add keys to BOTH language files simultaneously
5. **Verify after migration** — run `cmd /c "npx tsc --noEmit --skipLibCheck 2>&1"`
6. **Key naming** — `namespace:section.camelCaseKey`, keep flat within sections
